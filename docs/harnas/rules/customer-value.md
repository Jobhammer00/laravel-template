# Customer value

- Everything that gets built or designed is done **with the customer value in
  mind**. When a prompt says "this and this has to be made", make sure you know
  what the customer value is.
- Customer value states **why the client wants it** and **why the client is
  going to use it**.
- It does two things: it adds context to the project, and it makes the
  developer think about the value of what they deliver.
- So: not a dumb little chart added for its own sake, but a chart added so they
  have the right insights into the year's figures. Not "an edit modal exists",
  but an edit modal for this part so the client can easily see what is being
  edited without moving to a new screen.
- That kind of reasoning must be **properly described and properly thought
  through** by the developer.

## When customer value is missing

- If an assignment arrives without a stated customer value, **ask for it first
  and do not start building**. No code before the customer value is clear.

## Division of labour

- The **developer focuses on customer value**.
- The **AI solves the technical side**.
