# Decided at the start of each project

Some things are not fixed by this harness. They are settled per project, by the
developer, at the start — not improvised halfway through.

- **Theming** — set up at the start of every project, from the client's theme
  guide. See `rules/theming.md`.
- **Authorisation** — how roles and access work is determined at the start of
  the project by the developer.
- **Multilingualism in the application** — whether the app is multilingual is a
  per-project call by the developer. (The data-side consideration in
  `rules/database.md` still applies regardless.)
- **Where credentials live** — this differs per credential, so it is decided
  per credential by the developer. (Never in documentation or transcripts —
  see `rules/documentation.md`.)
- **Delivery process** — branching and reviews differ per project and are set
  up by the developer. What counts as done is **not** a free choice: the floor
  in `rules/definition-of-done.md` always applies, and a project may only add
  to it.
